# 随行帮办 · AssistGuide

> 面向数字弱势群体的 **AI 跨应用办事导航 Agent**。
> 说一句话，办成一件事——不是告诉老人「在哪办」，而是看着屏幕告诉他「手指点这儿」。

## 1. 它解决什么问题

老人办一件政务事项的真实路径是：打开 App → 在十二宫格找入口 → 翻 24 项长列表 → 读长文须知 → 填 6 个表单格 → 人脸核验 → 风控弹窗 → 提交。

其中任何一步走错，都没有人告诉他错在哪。现有方案要么依赖子女在场（不可规模化），要么是电话热线（无法定位到具体按钮），要么是教程视频（与他手机上的界面不一致）。

**随行帮办把「搜索引擎式的答案」换成「执行闭环式的导航」**：读当前屏幕 → 判断下一步 → 只指一个控件 → 听不见就语音播报 → 走错了当场拉回来 → 卡死了生成求助话术。

## 2. 三个不做

这是产品最重要的边界，也是评委最该记住的一句话：

| 场景 | 普通 AI 助手 | 随行帮办 |
| --- | --- | --- |
| 要付钱 | 帮你点 | **停手**，只念金额与收款方，密码一个字不看 |
| 要刷脸 | 帮你操作 | **停手**，说明「必须本人在场」，并提示反诈 |
| 要验证码 | 帮你填 | **停手**，提示验证码只给官方应用 |

技术上由领域层的硬编码护栏保证：模型说得再好听，也要过 `guardrails.ts` 这一关。

## 3. 快速开始

> **只想看效果？** 双击桌面上的 `启动随行帮办.bat`（或在项目目录执行 `npm run launch`）。
> 它会自动完成「环境自检 → 按需构建 → 启动服务 → 打开浏览器」，关掉窗口即停止。
> 附加参数：`--check` 只自检不启动；`--port=8899` 换端口；`--no-open` 不弹浏览器；
> `--skip-build` 跳过构建检查。

```bash
# 1. 依赖
npm install

# 2. 配置模型通道（不配也能跑，自动降级为规则引擎）
cp .env.example .env
#   填入 LLM_API_KEY（默认对接阿里云百炼 OpenAI 兼容端点，模型 qwen-plus）

# 3. 开发模式（API 8787 + 前端 5173，前端自动代理）
npm run dev

# 4. 生产模式（单端口，前端由 API 托管）
npm run build && npm start
#   打开 http://127.0.0.1:8787
```

演示动作：点「我想问一下低保那个复核」→ 跟着右侧大字指令点手机屏幕上的高亮处 → 到人脸核验时本人按下「开始核验」，会真实调起摄像头做圆形取景核验（无摄像头时自动降级为演示画面）；也可以试着说一句无关的话（比如「今天天气不错」），看它如何拒排而不装傻。

想看 AI 真的在决策：输入 **「我想申请高龄老人津贴」**（事项库没收录）。模型会照着屏幕库现场排一条路，
复述行下方出现蓝色「AI 现场规划」标记；点到没有后续页面的那一步时，它会停下来把材料清单念给你，
并说明「再往后的页面我没见过」。

## 4. 工程校验

```bash
npm run lint        # ESLint（含 no-explicit-any、类型导入一致性）
npm run typecheck   # 前后端两套 tsconfig，strict + noUncheckedIndexedAccess
npm run test        # Vitest：220 项，覆盖护栏、规则引擎、契约、编排、AI 规划校验、相关性拒排、提问识别与问答过滤、屏幕与导航一致性、引导链路首尾相接、起手页常办事项、熔断降级、限流、无障碍、内存上限、埋点轮转、用量统计、长期档案与提示词处置
npm run smoke       # 端到端：意图→引导→纠偏→护栏→救援→完成（需先启动服务）
node scripts/capture.mjs  # 用无头浏览器走完流程并逐屏出图
node scripts/probe-zero.mjs    # 零学习三件套的真实点击验证（含「下一步」连按、语音失败降级）
node scripts/shot-memory.mjs   # 长期档案：记住 → 刷新再认 → 忘掉（跨会话验证，不认三步之外的答案）
npm run launch -- --check # 启动器自检：环境、构建产物新鲜度、端口占用，不启动服务
```

> 测试默认串行执行（`vitest.config.ts` 的 `fileParallelism: false`）：并发 worker 会同时写系统临时目录的
> SSR 缓存，在受限文件系统沙箱下触发 `EPERM`，表现为部分测试文件静默不执行。串行代价约 1.2 秒，
> 换取本机与 CI 结果一致。

CI（`.github/workflows/ci.yml`）在 Node 20/22 双版本上跑 lint → typecheck → test → build → 冒烟。

## 6. 关键设计

**AI 在决策层，但决策要过闸门。**

模型干三件事：理解意图、**规划路径**、组织措辞。前两件都产出「动作」，因此都不能直接生效：

| 环节 | 模型产出 | 谁说了算 |
| --- | --- | --- |
| 已收录事项（4 件） | 只改措辞 | `guide-engine` 的确定性流程图决定点哪儿 |
| **未收录事项** | **现场排步骤** | `plan.ts` 校验后才允许执行 |
| 所有话术 | 一句话指令 | `sanitizeAssistantText` + 高危词过滤 |

事项库只有 4 件，可老人要办的事远不止 4 件。所以说「我要办高龄津贴」时，产品不会回答「我没学会」，
而是让模型照着屏幕库现场排一条路——但排出来的每一步都要过三道闸：

1. **屏幕契约**：`screenId` 与 `targetControlId` 必须真实存在。指一个不存在的按钮，结构上不可能发生。
2. **语义相关**：控件存在还不够。低保复核的表单页确实有「申请人姓名」这一格，但它是别人的表——
   拿它办高龄津贴，控件全对、业务全错。校验器用二字重叠判断「这屏跟这件事是不是一码事」，
   对不上就在那一步**截断**，宁可少走一步，不可走错一步。
3. **护栏只增不减**：付款、人脸、验证码、授权、证件号，推断结果与模型自报取并集，
   模型没有任何权限把一道强制护栏降回普通点击。

截断不是失败。被截断时产品会说清楚：「要带的是身份证、户口簿、本人银行卡。再往后的页面我没见过，
不敢瞎指，您卡住了就点『我卡住了』。」——**承认边界比假装全能更值得信任**，
这也是演示时最容易被记住的一段。

**屏幕即契约。**
`SCREENS` 同时驱动前端渲染与服务端校验。Agent 指向的控件 id 必须真实存在于当前屏幕，否则直接判为非法动作。

**点得动，回得来。**
演示应用不是四张截图。服务大厅的每个宫格通向对应主题专区，专区里每个条目要么接上已接入的真实流程，
要么落到一页说明与人工求助——**没有「点了没反应」的入口**。底部导航被做成整台手机的固定部件，
表单页、风控页、结果页都在，老人在任何一层都能回首页、去服务、看我的。
这条约束写成了契约测试（`tests/navigation.test.ts`）：谁再加一个点不动的入口，CI 当场拦下。
布局也按此校准：手机高度跟随视口（`clamp(520px, 100vh - 222px, 748px)`），
1366×768 的笔记本上底部标签栏不会被指标栏压住。

**零学习成本：把「学习」从老人身上挪到 Agent 身上。**

适老产品常见的做法是把界面做大做简，再配一段教学。但教学本身就是成本，
而且它假设老人愿意学。真正拦住老人的是四道坎，每道坎都不该靠「教」来解决：

| 坎 | 老人的实际表现 | 常见做法 | 这里的做法 |
| --- | --- | --- | --- |
| 不知道说什么 | 「我这个钱怎么没了」 | 提示「请说出您要办的事」 | 先开口，再把**扫出来的自己的事**摆成三张大按钮 |
| 说不清 | 方言、口齿、不会说「复核」「资格认证」 | 让他「再说一遍」 | 第二次听不清就换路子，改问「是不是这一件」（点选代替表达） |
| 找不到 | 你说「点社保服务」，他在九宫格里翻了半天 | 高亮目标按钮 | 目标按钮在**屏幕底部再长出一个**，位置永远不变 |
| 怕点错 | 点错一次就不敢再点 | 报错、重来 | 不惩罚，直接绕回来；卡住了有一句带着上下文的人工求助话术 |

三处落地：

1. **起手页只有一条路**（`components/GuideCard.tsx` 的未开始态）。
   不做搜索框、不做九宫格、不做说明段落，只有一个大按钮「按这里说话」，
   下面三张卡是**刚刚扫出来的真实待办**（`web/zero.ts` → `quickTasksFrom`），
   写着「本月水费 · 还有 6 天 · 这周内办」。示例句是别人要办的事，老人认不出自己属于哪一句；
   自己的事他一眼就认得。说明文字收进「它凭什么能带得动我」，留给评委，不占老人的视界。
2. **说不清就做选择题**（`ask-layer`）。语音连续两次失败、或设备根本不支持语音，
   不再重复「请您再说一次」，而是弹出一屏事项让老人点——**表达不出来，但认得出来**。
   这是「不会用 AI」的人唯一能真正开始的方式。
3. **下一步大按钮**（`components/ScreenView.tsx` 的 `next-bar`）。
   高亮环解决了一部分「找不到」，但目标可能在小屏下半截、可能是第九个图标，老人还是要找。
   所以把当前目标复制成屏幕底部一个固定位置的大按钮，写着「点「更多服务」」。
   **老人全程只需要学会按同一个位置**——这件事不用学。它由 `GuideAction.targetControlId`
   驱动，目标是一格表单时自动变成「填「申请人姓名」」。

这条链路曾经真的断过：水费流程从首页点「更多服务」，落点写的是账单页，
而下一个节点的起点是「全部服务」——界面上那一跳不存在，「下一步」走到第二步就没了。
现在 `tests/catalog.test.ts` 里有一条契约：**每个节点的落点必须正好是下一节点的起点**，
每个目标控件必须真实存在。改流程改到两头对不上，CI 当场拦下。

**四种管家能力：差别不在多几个入口，而在「谁先开口」。**

政务 App 的组织方式是「目录」：先分类、再找入口、然后自己办。它假设用户知道
「这件事属于哪个部门、在哪一栏」。老人恰恰不知道。所以本产品把四种能力做成
**一句话就能进**的通道（`domain/tools.ts` 路由），而不是又四个菜单：

| 时刻 | 闽政通式做法 | 随行帮办 |
| --- | --- | --- |
| 办之前 | 提交 → 等 3 个工作日 → 退回 → 补材料 → 再提交 | **办前体检**：现在提交会不会退、退在哪一格、去哪儿补 |
| 办之中 | 自己办，或把账号交给子女代按 | **协办码**：家人远程看得到、能说一句，但按不按仍由本人 |
| 办之后 | 提交成功即服务结束 | **守护日历**：到期、年检、复核自己排好，开场先提醒 |
| 办事之外 | 反诈宣传专栏，要自己对照 | **可疑话术判别**：把对方说的话学一遍，直接判是不是诈骗 |

四条通道共用一个入口：用户说「我这低保复核的材料还差什么」，路由命中体检；
说「我最近有什么事要办」，命中日历；说「我女儿能不能远程帮我弄」，命中协办；
说「刚才有人打电话说我医保卡涉案」，命中反诈——**风险优先**，因为钱出去了回不来。

三处刻意的取舍：

- **体检只说「会被退回」，不说「能批」**。结论里写明「以受理窗口为准」，
  一次办成率是估算值并标注区间，不做成假精确的 87.3%。
- **协办码在类型层面就没有「代按」这个字段**（`CollabHint` 只有 `text`）。
  家人能发一句话，不能替他点提交、刷脸、输密码——边界写在数据里，不写在文案里。
- **反诈用规则加权而不是纯模型**：漏判的代价是倾家荡产，误判的代价是老人不敢用手机，
  两个方向都必须可回归测试。所以「我要交水费」永远判不出诈骗，而「转钱到安全账户」判得出。

**三条链路互为兜底。**
模型通道（DashScope）→ 规则引擎（确定性流程）→ 人工（携带上下文的话术 + 12345）。任何一环失效，用户仍有下一步可走。

## 7. 已知限制

- 演示端的「屏幕」来自本地屏幕库，生产环境需接 Android `AccessibilityService`；接口已按无障碍节点语义定义（见 `docs/adr/0002`）。
- 事项库目前覆盖 4 个高频事项，新增事项需补充流程图与契约测试，未做开放式自动规划。
- 基线指标（12 步 / 8 分 40 秒）为设计假设，需在 11 月完成 30 人可用性测试后校准。
- 会话状态存在进程内存，重启即失效；生产需换 Redis。
