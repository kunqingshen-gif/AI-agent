一、指标定义与采集方式

指标定义（怎么算）采集位置当前值 / 判读
引导准确率 Agent 指向的控件 ID 与流程图声明的目标控件一致的比例 契约测试（tests/navigation.test.ts）+ 埋点 guide.issued 的 targetControlId 100%（12/12 节点）。这是硬约束：流程图里写哪个控件，界面就只高亮哪个，模型无权改动
响应延迟 引导接口从收到请求到返回的时间，含模型调用与 HTTP 往返 埋点 guide.issued.latencyMs；/api/metrics 输出 p50 / p95 模型通道 P50 2037ms / P95 2804ms；规则通道 P50 2.3ms；改写缓存命中 0ms（不发起调用）
调用成本 累计 token ÷ 模型调用次数 /api/metrics → llm.tokens / llm.calls 23 次调用共 14281 tokens，均值 621 tokens/次。规则通道与缓存命中为 0 调用
纠偏成功率 走错后 1 步内回到正确流程的比例 埋点 rescue.triggered，含误入屏幕与纠偏话术 100%（演示用例）。纠偏不是「返回」两个字，而是说明「这里是医保，办低保要回上一页」
护栏命中 支付、人脸、验证码、授权协议等节点被降级为「本人确认」的次数 埋点 guardrail.blocked；规则在 guardrails.ts 硬编码 低保复核 2 次（人脸 / 身份）、生活缴费 2 次（支付 / 确认）。命中后模型无法代按
说错率 结果页反馈「它说错了」占全部反馈的比例，按人头计数，改主意以最后一次为准 埋点 feedback.given；/api/metrics → quality.wrongRate 三档分开统计。「没办成」多卡在系统或材料，是流程问题；「说错了」才是措辞或定位问题，两者混算会把可修的平均掉
通道可用性 模型不可用时流程能否走完 熔断器 + /api/meta；无密钥冒烟测试 可完整走完。连续失败即熔断 60 秒，界面徽标变为「模型降级 · 规则兜底」并如实告知

curl /api/metrics上述延迟、token、反馈与埋点计数的实时快照

三、口径说明（避免误读）

① 用 P95 而非平均值：引导是有人盯着屏幕等的同步调用，一次 5 秒长尾会被平均值藏起来。② 失败分两类记账：network 与 timeout 分开统计——前者改配置永远改不好，混算会掩盖真因。③ 样本量如实标注：本页为 2026-10-31 20:22 运行快照，真实用户可用性测试尚未开展（见说明书 7.4 节）。
