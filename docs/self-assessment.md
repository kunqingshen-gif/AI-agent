# 生产级 Agent 自评（21 项 · 百分制）

> 评分依据：**代码实证 + 测试 + 探针**，不是自我感觉。
> 每项写清「有什么证据」「差在哪」，评委追问时可当场翻文件。
> 评分尺度：5 = 生产级；4 = 完整但缺一环；3 = 可用但明显欠账；2 = 雏形；1 = 几乎没有。

## 总分

| 口径 | 分数 | 说明 |
|---|---|---|
| **按「生产级 Agent」标尺** | **69.8 / 100** | 本文件逐项加权得出 |
| 按创新创业赛评审逻辑 | 约 79–82 | 创新性、社会价值、完成度权重更高，工程欠账不致命 |

**一句话定位：智能与体验是强项，工程化与运营是欠账，落地受资质约束。**

## 改进优先级（按投入产出比）

| 序 | 改进 | 工期 | 提分 | 为什么排这个位置 |
|---|---|---|---|---|
| 1 | **一条命令复现**：`npm run demo:check` → verify + smoke + 三探针 + 出 HTML 报告 | 0.5 天 | 不直接提分，但**直接影响评委信任** | 现在要手工跑 4 条命令。评委最怕「只能在你电脑上跑」 |
| 2 | **反馈闭环 0→1**：结果卡加「办成了/没办成/它说错了」，写埋点，指标出纠正率 | 0.5 天 | 六类 25 → 55 | 投入最小、提分最大。一个按钮把「运营迭代」从无到有 |
| 3 | **配置外置**：`config/prompts.json` + `config/catalog.json`，启动 zod 校验 + version 字段 | 1 天 | 二类 70 → 85 | 兑现「业务人员改 JSON 不改代码」，这是唯一可信的证明 |
| 4 | **记忆分层**：抽 `ProfileStore`，档案可查可改可过期，改完立即影响引导措辞 | 1.5 天 | 一类 72 → 80 | `digitalLiteracy` 己经在用，只是不让改。补写接口即可见效 |
| 5 | **成本指标**：tokens / p95 延迟 / 单次办事成本 / plan 拒绝率进 `/api/metrics` | 0.5 天 | 三类 65 → 72 | 数据已经在 `dashscope.ts` 里，只差聚合 |
| 6 | **版本灰度**：promptVersion 进埋点，按 sessionId 哈希分流 | 1 天 | 六类 55 → 70 | 让「A/B 对比」在答辩时可演示 |

**做完 1–5（4 天），总分约 69.8 → 78。** 第六项看时间。

## 不该再投入的

- 加更多事项、更多屏幕：边际收益已接近 0，评委不会因为多 10 个入口加分。
- 接真实政务接口：做不成，且做了会引出合规问题。
- 换更花哨的 UI：当前视觉已经足够，再加装饰会削弱「可信」的观感。
