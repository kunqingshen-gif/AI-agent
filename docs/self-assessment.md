# 第二轮自检（2026-11-10）：四类使用者 × 多模态

> 全部观察都落在真实页面、真实交互或可指名的代码上；
> 证据可用 `node scripts/probe-zero.mjs`、`probe-guardian.mjs`、`probe-multimodal.mjs` 复现。

## 一、四类使用者各看到了什么

### 1. 70 岁以上、第一次用智能机的老人

1. **起手页只有一条路**：一个最大的「按这里说话」，下面三件「您自己的事」，每件带倒计时（实测「本月水费还有 6 天 · 这周内办」）。没有搜索框、没有九宫格。
2. **说不清就换法子，不逼重复**：连说两次听不清，自动换成「您要办哪一件」的三张卡（`.ask-layer`），点一下就真的开始办。
3. **不要求理解「下一步」**：大按钮直接写控件名——「点『民政服务』下一步 →」，屏幕上还有一个蓝色视点落在那个方块上。
4. **说方言时曾被自己的机器"翻译"成提问**：粤语「我唔识点样办低保复核」被逐词翻成「我不会怎么办…」，「怎么办」触发问答通道，老人明明是要办事，却得到一段解释。**本轮已修**（见下）。
5. **求助话术曾经说错自己的年龄**：话术写死「78 岁一个人住」，档案是 68 岁；照着念给 12345，对面按 78 岁查政策。**本轮已修**。

### 2. 陪同的子女

1. **协办码是"只读陪同"**：6 位、排除 0/1/O/I，屏上明说「看得到但按不了」；家人接入后只出现气泡，手机仍停在原页，没有被代按（probe-guardian 用页面标题与 `.collab-bubble` 双重验证）。
2. **办前体检直接说会被退回的那一份**：「家庭收入证明会被退回」「最低生活保障证明办到一半会失效」，并给出「提前续期」的补救路径——这是子女最想替老人先问的。
3. **看不到协办码的有效期/次数**：目前只有一次性演示入口，没有「多久失效、能叫几个人」。
4. **档案里的方言字段此前是死字段**：`UserProfile.dialect` 声明了，语音却固定 `zh-CN`。本轮已接进 `speechLangOf`。

### 3. 社区 / 政务窗口工作人员

1. **预判不冒充审批**：「一次办成率」「以受理窗口为准」把系统判断和窗口裁量分开，减少「你们 App 说能办」的争执。
2. **可疑话术现场可用**：输入「有人让我把钱转到安全账户」，给出「这是诈骗」、命中特征、96110、可转发家人——窗口可以当场演示给老人看。
3. **材料清单写死在 `catalog.ts`**：辖区多要一份居住证明，就要改代码发版（与第一轮判断一致）。
4. **日历排序没有依赖关系**：「低保证明到期」与「低保资格复核」并列展示，窗口知道要先续证明再复核，产品只排序、不解释先后。

### 4. 评委（技术视角 / 产品视角）

1. **护栏可解释、可验证**：`inferGuardrail` 的顺序（人脸 > 付款 > 验证码 > 本人确认 > 授权 > 证件号）写在代码里；模型自报的 guardrail 只取并集，不能减。
2. **护栏此前依赖命名契约**：`screenId.endsWith('.face')`——把 id 改成 `.verify`，护栏静默失效。本轮改成读屏幕标题与正文标题（`isBiometricScreen`），并加了「文案里没有人脸字样也照样拦」的测试。
3. **计划验证器是「截断而非整单拒绝」**：控件的存在性、跨屏可达性、语义相关性三道闸；本轮补了概念层，解决「老年津贴 / 养老补贴」与「高龄津贴」被二字重叠误判、正确步骤被截断的问题。
4. **离线仍有完整闭环**：规则引擎 4 条流程 + 本轮新增的纯函数词典；模型不可用时，方言与同音纠正照样生效。
5. **欠账依旧明显**：`App.tsx` 约 1000 行、`assist-service.ts` 约 1400 行；被问「怎么加第 5 个流程」时，答案仍是「改 TS 再发版」。

## 三、多模态创新点：代码、演示入口、降级

### ① 方言 / 同音 / 老人叫法归一（`src/web/speech-fix.ts`）

- **做什么**：在「理解意图」之前，用一张确定性的词典把三类偏差修回标准说法——方言词（粤语/四川话/闽南语）、同音字（高领→高龄、水非→水费、养老今→养老金）、老人自己的叫法（老人钱→高龄津贴、年审→复核）。改了什么必须显示在屏上，不静默改话。
- **为什么不用大模型做**：模型能听懂，但没 key 时整条链路走规则引擎；容错若只写在提示词里，降级那一刻恰好失去容错。词典是纯函数，离线、可测、行为稳定。
- **取舍**：只改「确定会被听错的词」，不做通用拼音模糊匹配——模糊匹配会把「高领毛衣」改成「高龄毛衣」，老人会直接放弃。
- **演示入口**：输入框输入「我唔识点样办低保复核」→ 开始；屏上出现黄色校正条「我听成「唔识点样办」，按您的常用说法记作「想办」」，紧接着确认「低保定期复核」。也可说「我要办高领津贴」「老人钱到了没有」。
- **验证**：`npx vitest run tests/speech-fix.test.ts`（8 项）；`node scripts/probe-multimodal.mjs` 第一段。
- **降级**：识别不出方言就按普通话处理，不猜；词典未覆盖的说法原样交给模型/规则；`localStorage` 与网络都无关。

### ② 语音与屏幕文字的联合校验（`normalizeUtterance` 的 `via` 字段）

- **做什么**：同一句纠正，如果标准词确实出现在**此刻这一页**的标题/控件/正文里，标记为 `via: 'screen'`，屏上写「按这一页的写法记作…」；否则写「按您的常用说法」。这是把「听到的」与「看到的」交叉验证——只有前端同时握着两者。
- **为什么**：给用户一个可核对的理由，也给埋点一个可区分的信号；改错时能追到是词典错还是屏幕证据错。
- **演示入口**：在高龄津贴列表页说「高领津贴」，校正理由显示「这一页的写法」；在起手页说同样的话，显示「您的常用说法」。
- **降级**：拿不到屏幕词表（页面未渲染/异常）时退回 `lexicon`，纠正本身不受影响。

### ③ 视觉可达性：指之前先确认「看得见」（`src/web/components/SightLine.tsx`）

- **做什么**：Agent 决定高亮某个控件后，用 `getBoundingClientRect` 量它是否真的落在 `.app-body` 的可视区内；不在就替老人把屏滚过去，并在屏幕上方标注「翻到这一处才指给您」。滚动只做一次，不跟用户抢滚动条。
- **为什么**：屏幕模型里有这个控件 id，不等于老人眼里有这个按钮。表单页的「提交」常常在下一屏，指了等于没指。
- **演示入口**：说「我想办低保复核」→ 连按「下一步」直到表单页；当目标在屏幕下方时，屏内容自动上移并出现蓝色小标。
- **验证**：`node scripts/probe-multimodal.mjs` 第二段——实测 3 步引导中 0 步落在屏外，并记录 1 次自动翻屏；若目标本来就可见，则不滚动、不出现标注。
- **降级**：纯几何计算，无模型、无网络依赖；找不到滚动容器或元素未渲染时保持原行为（不滚动），最坏是没帮上忙，不会指错。
