# ADR-0001 · 决策归规则，措辞归模型

- 状态：已采纳
- 日期：2026-10-27
- 决策者：架构组

## 背景

产品要在老人面前「指一个按钮」。这个动作必须正确——指错一次，用户就不再信任；而在答辩现场指错一次，产品就失去说服力。

候选方案有三种：

1. **全模型驱动**：把屏幕结构塞进上下文，让模型直接输出「点哪个控件」。灵活，但不可复现：同一屏幕两次调用可能给出不同控件；模型还可能指向不存在的控件。
2. **全规则驱动**：预置流程模板，逐节点硬编码话术。可靠，但话术僵硬、无法适应走错路径的长尾组合。
3. **混合**：规则决定「点哪儿」，模型决定「怎么说」。

## 决策

采用方案 3：

- `domain/guide-engine.ts` 基于「当前屏幕 + 已完成节点 + 已填槽位」计算唯一解，输出 `targetControlId`；
- 模型只接收「这一步的目的 + 目标控件文案」，产出一句话术；
- 模型输出必须通过 zod 结构校验、高危词过滤、长度裁剪，任一不过即回退模板；
- 护栏节点完全跳过模型，只使用经审阅的模板。

## 后果

**正面**

- 决策可单元测试，可复现，CI 可锁死；
- 模型失效时产品退化为确定性程序，功能不中断；
- 演示不翻车：断网、超时、返回乱码，用户看到的仍是可执行指令。

**负面**

- 灵活性受限于已有流程图；未知事项无法自动规划。这是有意取舍（见 PRD 非目标）。
- 需要维护两套话术（模板 + 模型偏好），存在一致性成本。

## 备选方案被否原因

全模型驱动在演示环境中无法保证「两次点击给同一答案」，这直接违背「导航」这一产品隐喻——导航仪不能每次重新找路。
