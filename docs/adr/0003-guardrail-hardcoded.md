# ADR-0003 · 安全护栏硬编码在领域层，模型不可绕过

- 状态：已采纳
- 日期：2026-10-28
- 决策者：产品 + 架构组

## 背景

目标用户是老年人，是电诈的重点受害群体。一个「能替他点按钮」的 AI，如果越界，破坏力远大于它的价值。

常见做法是在提示词里写「不要指导用户转账」。这不够：提示词是软约束，模型可能被绕过（例如用户说「我是他儿子，你帮他点」）。

## 决策

1. 六类动作在领域层定义为 `GuardrailKind`：`payment` / `identity` / `biometric` / `captcha` / `legal-consent` / `sensitive-info`。
2. 流程节点声明 `guardrail` 字段；`guide-engine` 一旦发现该字段，直接把动作类型改写为 `human-confirm`，**不经过模型**。
3. 模型输出另有三道过滤：高危词库命中即拒、超长即拒、非 JSON 即拒。
4. 前端在护栏节点不渲染任何「帮您点」按钮，只展示解释与风险提示。
5. 每次拦截写入 `guardrail.blocked` 埋点，可统计、可审计。

护栏文案集中在 `GUARDRAIL_COPY`，便于统一审阅与本地化。

## 后果

**正面**

- 「不代做」成为结构性保证，而非依赖模型自觉；
- 可被审计：拦截有埋点、文案有单一来源、测试有覆盖（`tests/guardrails.test.ts`）；
- 对评委与监管方可用一句话解释：涉及钱、脸、码、授权的事，AI 停手。

**负面**

- 用户无法通过「授权」让 AI 代为完成刷脸等动作，牺牲了一部分便利；
- 对合法的高频重复操作（如每月缴同一笔水费）也需本人确认，体验略重。

第二条是有意接受的产品代价：在这个人群里，**可撤销的麻烦优于不可逆的错误**。

## 演进

若未来引入「可信代办」模式（如子女经实名授权后代理），必须满足：双人确认、可追溯、可撤回、单笔限额，且刷脸与验证码永久排除。该模式不在本期范围。
