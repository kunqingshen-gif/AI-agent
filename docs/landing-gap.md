# 离真实落地还差什么

> 这份文档不是「未来展望」，是**差距清单**。
> 每一条都写清：现在是什么、真机要什么、卡在哪、谁来解决。
> 写在答辩 PPT「风险与路径」页可以直接用；被追问时照着答不会翻车。

## 一句话结论

**能力已经跑通，通道还没打开。**

产品最难的那部分——「读懂一屏界面、算出一个具体控件、说一句老人听得懂的话、并且坚决不替他按」——在这个版本里是真的，有 173 项测试和真实坐标点击探针兜着。缺的是把它从「模拟屏」接到「真实屏」的那几个接口，而这些接口**不是写代码能解决的**，是资质和授权问题。

诚实的说法：**这是一个能演示、能验证、但还不能上线的产品。**

## 二、三道硬门槛（按难度排）

### 门槛一：政务数据不是「申请就有」

想做「材料够不够、什么时候到期、办到哪一步了」，必须拿到三类数据：事项办理要求、电子证照、办件进度。这三类**都不对个人开发者开放**。

**因此真实路径只有两条：**
- **A. 做外挂，不碰数据。** 只读屏幕可见内容 + 用户自己填的材料清单。这条能绕开资质，代价是「材料是否有效」只能靠用户拍证件、靠规则判断，不能查证照库。本版本走的就是这条，`preflight.ts` 的 `expiresAt` 逻辑正是为它设计的。
- **B. 找运营方合作。** 挂靠政务服务平台或社区/银行网点，用他们的资质接数据。

**答辩时该这么说**：「我们不假设能拿到政务数据。产品在『只看得见屏幕』这个最苛刻的假设下设计，拿到数据只会更准，不会推倒重来。」

### 门槛二：无障碍权限是最难过的应用商店审核

`AccessibilityService` 能读全屏内容，是 Android 上权限最高、滥用最严重的权限之一。Google Play 与国内商店都要求：用途必须直接服务残障/适老，且不得用于自动化操作他人应用。

**这一条恰好对本产品有利**：我们**明确拒绝代按**（`CollabHint` 类型里根本没有 `controlId` 字段，代按在数据层不存在），定位是「指路」而不是「代操作」。这是审核时最有说服力的材料。

### 门槛三：政务界面会变，而它变得比你快

闽政通类应用一年多次改版。屏幕模型一旦对不上真实界面，「下一步」就会指错——**指错比不指更糟**，老人会失去信任。

**必须有的兜底**：真实落地时不能只靠人工维护屏幕模型，要加「界面变了」的自检——找不到目标控件时立刻降级为「我不确定，您看是不是这一项」+ 转人工，而不是硬指。本版本已有 `resolveTarget` 兜底到列表页 + 「我卡住了」救援链路，但**没有做改版检测**，这是真实落地必须补的一块。

## 三、成本与可持续性

| 项 | 量级 | 说明 |
|---|---|---|
| 大模型调用 | 约 0.004 元/次办事（qwen-plus，输入约 1.2k token） | 一次完整办事约 6–10 次调用，单次办事成本 &lt; 0.05 元 |
| 服务器 | 单机可撑演示；千人日活约 2 核 4G | 会话在内存，扩副本要先换 Redis |
| 端侧 ASR | 一次性集成 + 按调用计费 | 方言模型需定制，是最大不确定项 |
| 人力 | 屏幕模型维护 0.5 人（每个合作方 App 每年约 30 人时） | 这是长期成本，不是一次性 |

**商业模式没验证过。** 诚实的判断：最可能付费的是**社区/街道、银行网点、养老机构**（他们有人工帮办的成本），不是老人自己。按「减少一次人工帮办」计价，比按次收老人钱更成立。

## 五、如果评委问这五个问题

**Q：这东西现在能用吗？**
「能演示，不能上线。差的不是功能，是三个接口：真机无障碍、政务事项库、持牌核身。这三个都不是写代码能解决的，所以我没有假装它已经能上线。」

**Q：老人真的会用吗？**
「我们的假设是**他不需要会用**。全程只需要按屏幕最下面那个位置不变的大按钮。这一点在探针里被验证过：连按三次不中断、底部导航没被压住。」

**Q：指错了怎么办？**
「指错比不指更糟。所以找不到目标时立刻降级成『我不确定，您看是不是这一项』，并有『我卡住了』转人工。但改版自检还没做，这是 P2 必须补的。」

**Q：数据安全怎么保证？**
「当前版本不采集任何真实证件：演示档案里手机号是打码的，没有身份证号。真机版本的原则是**证件不出端**——OCR 和比对尽量在手机本地完成，只上传判断结果。人脸核身一定走持牌机构，我们不碰。」

**Q：凭什么比闽政通好？**
「不是比它好，是**它做不到的那部分由我们做**。闽政通的服务终止于『提交成功』，后面的到期、复核、材料失效全靠老人自己记。我们在它前面（先去哪、带什么）和后面（什么时候还会再来一次）各接一段。」
